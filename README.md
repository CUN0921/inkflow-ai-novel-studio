# 墨流 · AI 小说工作台

一个面向个人长篇创作的本地 AI 系统。它把全书主线、分卷目标、近期章纲、正文、已发生事实和伏笔分开管理，并按照“写作 → 检查 → 保存记忆”的流程自动推进。

## 立即启动

需要支持 SQLite 的 Node.js 22.5 或更高版本，不需要安装任何依赖。Windows 可以直接双击 `启动墨流.cmd`：启动器会查找已安装的 Node、本项目 `runtime/node.exe` 以及本机 Codex 附带的兼容运行环境；服务就绪后自动打开浏览器。重复双击会复用已有服务，启动窗口关闭后服务仍在后台运行。

端口从 `.env` 或环境变量 `PORT` 读取，默认 4310。启动诊断保存在 `data/server.log` 和 `data/server-error.log`。端口被其他程序占用时会显示提示，不会停止其他程序。

```powershell
cd ai-novel-studio
node server.mjs
```

浏览器打开 <http://127.0.0.1:4310>。首次启动会创建一部演示作品，所有数据保存在本机的 `data/novels.db`。

## 连接真实 AI

点击左下角齿轮打开“模型与审稿”，可分别填写故事规划、正文写作、审稿整理、网络查重的 API 地址、模型名称、协议和密钥。保存后后续请求立即使用新配置；“测试已保存的连接”验证已保存配置。已有密钥不回显，留空保留，也可勾选清除。

同一设置窗口还可以分别调整每个角色的单次输出 Token 预算，范围为 256–32768，并选择推理模式（自动、关闭思考、最低、低、中、高、更高或最大）。输出预算包含模型思考 Token；使用 DeepSeek 时，审稿整理默认关闭思考，避免推理占满预算而没有生成 JSON。其他服务商默认使用自动模式，可按接口能力自行选择。默认预算为：规划 8000、正文 24000、审稿 6000、查重 6000。正文和重写会直接使用这里保存的预算；供应商模型自身的上下文窗口和单次上限仍可能更低。

界面配置保存在本机 `data/model-settings.json`（包含密钥，已被 Git 忽略），优先于 `.env`，重启仍有效。隔离运行时可用 `NOVEL_SETTINGS_PATH` 指定设置文件，默认随作品数据库保存在同目录。未从界面保存前，继续使用原来的 `.env` 设置。

“启用自动审稿”默认开启。关闭后不做文风评分或正文修订，但仍通过审稿整理模型生成摘要、人物状态、故事记忆和章节交接卡，保证下一章能够连续写作。旧章资料失效时，可以在章节编辑器中单独重新整理。

复制 `.env.example` 为 `.env`。最简单的方式是填写一组默认配置，三个任务共用同一个模型：

```text
OPENAI_API_KEY=你的密钥
OPENAI_MODEL=gpt-5.6-luna
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_PROTOCOL=responses
```

也可以分别配置四个任务：

```text
AI_PLANNER_MODEL=gpt-5.6-sol
AI_PLANNER_BASE_URL=https://api.openai.com/v1

AI_WRITER_MODEL=gpt-5.6-terra
AI_WRITER_BASE_URL=https://api.openai.com/v1

AI_REVIEWER_MODEL=另一个模型名称
AI_REVIEWER_BASE_URL=https://另一个服务商.example/v1
AI_REVIEWER_PROTOCOL=chat

AI_CHECKER_MODEL=支持网页搜索的模型名称
AI_CHECKER_BASE_URL=https://另一个服务商.example/v1
AI_CHECKER_PROTOCOL=responses
```

每个任务还可以设置自己的 `AI_PLANNER_API_KEY`、`AI_WRITER_API_KEY`、`AI_REVIEWER_API_KEY` 和 `AI_CHECKER_API_KEY`。不填写任务专属项时，自动使用对应的 `OPENAI_*` 默认值。

系统同时支持 `responses` 和 `chat` 两种协议。API 地址可以填写 `/v1` 基础路径，也可以直接填写完整的 `/responses` 或 `/chat/completions` 路径。保存 `.env` 后配置会自动重新加载；设置窗口会显示每个任务实际使用的模型、协议和接口地址，并可以发起一次最小连接测试。密钥不会返回浏览器，也不会写入作品数据库。Responses 请求设置了 `store: false`。

网络查重使用第四个 `checker` 任务模型，默认复用 `OPENAI_*`。也可以通过 `AI_CHECKER_MODEL`、`AI_CHECKER_BASE_URL` 和 `AI_CHECKER_API_KEY` 单独指定。该模型必须使用 Responses 协议，并支持内置 `web_search` 工具。

## 当前功能

- 多作品控制台、进度与字数统计
- 全书主线、世界规则、主要人物与分卷结构
- 每批扩展 1–10 章，可指定目标卷和本批剧情要求，并衔接已有待写章纲
- 按具体章节选择自动写作，队列持久保存；每章可自定标题、章纲、写作要求、目标字数与正文
- 每章都会生成章节交接卡；关闭质量审稿也会整理基础故事资料，下一章仍读取上一章结尾
- 每章可单独填写“开篇衔接要求”，重写前章后会自动使后续交接资料失效
- 逐章自动写作、责任编辑检查和有限返修
- 写作任务运行中同步刷新已生成字数、章节状态和当前阶段
- 规划分成“全书骨架”和“近期 10 章”两次生成，降低长 JSON 被截断的概率；截断或结构校验失败会在模型动态中明确标为失败并保留返回内容
- 正文在审稿前先保存为待审稿草稿；审稿失败可直接“重新审稿”，不会再次生成正文；重写候选稿也支持仅重新审稿
- 已发生事实与未来伏笔分开存储；记忆按相关性和重要度选择并支持置顶
- 正文中出现的新人物会加入人物档案，人物关系、目标、位置和状态随章节更新
- 章纲支持开场状态、出场人物、目标、转折、必写事件和结束状态；伏笔记录实际推进与回收
- 每条事实保留来源章节
- 故事记忆可按人物、事件、物品、认知、关系和时间线筛选
- 自动任务按写作、草稿保存、审稿和资料更新记录阶段；安全暂停、失败恢复并支持服务重启续跑
- 正文支持流式显示模型返回；达到输出上限时保留部分草稿并可继续续写
- 章节手动编辑与历史版本
- 任意已完成章节按自定义要求生成重写候选稿，对照后选择采用或放弃
- “创作依据”页面展示全书、分卷、章纲、记忆、伏笔和模型分工
- “模型动态”页面实时显示每次模型请求的任务、章节、状态、耗时、输出预算、用量、请求与返回内容；较长内容会标出已显示范围
- 写作按章号隔离未来知识；重写仅让审稿读取后续摘要，并保存实际资料快照
- 当前章节网络内容相似度检测，保留命中来源和片段
- 全文 TXT 导出
- 无密钥演示模式

## 验证

```powershell
node --test
```

本机浏览器回归测试 `node scripts/qa-start-create.mjs` 会使用独立临时数据库，验证缺少 Node PATH 的双击启动环境、重复启动、从旧章新建、重复提交保护和规划失败后的重试；需本机 Codex Playwright 运行环境和 Chrome。

建议先选择一章试写校准文风。修改旧章时，系统会将该章及后续记忆标为待复核，排除失效摘要，并创建影响检查记录。完整规则和可讨论的调整项见 [章节控制与章纲扩展逻辑](docs/章节控制与章纲扩展逻辑.md)。
